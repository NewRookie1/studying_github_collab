8 modules — complete guide

1

Setup: Git + GitHub in 5 minutes

Git = version control on your computer. GitHub = website to host repos and collaborate.

git --version
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
Mission: Create a GitHub account, install Git, run the 3 config commands above. Verify with git config --list.
2

Repos, Fork, Clone, Remote

A repository = project folder + history. Clone = download it. Fork = your own copy on GitHub. Remote = GitHub's address (called origin).

git clone https://github.com/NewRookie1/studying_github_collab.git
cd studying_github_collab
git remote -v
git status
git fetch origin
git pull origin main
Mission: Clone the demo repo above. Run git status and git log --oneline -5. You should see history.
3

Branching: the #1 collab rule

Golden rule: never commit directly to main. Create a branch per task: name/what-you-do, e.g. ana/add-bio.

git checkout main
git pull origin main
git checkout -b ana/add-bio
git branch          # list branches
git switch main     # modern way to switch
Naming: feat/…, fix/…, docs/…, or yourname/…. One branch = one PR.
4

Add, Commit, History

工作流程: edit → add (stage) → commit (snapshot) → push (upload). Write messages in imperative mood.

git status
git add practice/team-roster.json
git commit -m "Add Ana to team roster"
git log --oneline --graph -8
git show HEAD --stat
Good messages: “Add…”, “Fix…”, “Update…”. Bad: “asdf”, “final final v2”. Mission: edit practice/team-roster.json, commit on your branch.
5

Push, Pull, Fetch & Sync

git push -u origin ana/add-bio     # first push sets upstream
git push                            # after that
git pull --rebase origin main       # get latest main into your branch
git fetch origin                    # download without merging
git diff main...HEAD                # what will your PR change?
Mission: Push your branch. Open GitHub → you’ll see a yellow “Compare & pull request” banner.
6

Pull Requests: how teams merge

A PR = proposal to merge your branch into main. Teammates review, comment, approve, then merge.

  1. Push branch → Compare & pull request
  2. Title clearly: “Add Ana bio + photo” — link issue with Closes #3
  3. Ask for review, respond to comments, push fixes (same branch updates PR)
  4. Squash & merge or Merge commit → delete branch
Review etiquette: be kind, suggest code with ```suggestion, approve when LGTM. Try Lab 3 below.
7

Merge conflicts (you will get them!)

Conflict = both changed the same lines. Git pauses and asks you to choose.

<<<<<<< HEAD
Hello from main
=======
Hello from your branch
>>>>>>> ana/add-bio

Steps: git pull origin main → open file → delete markers, keep correct code → git add → git commit → git push. Practice in Lab 4 and in practice/conflict-demo.txt.

8

Team tools: Issues, Projects, Actions, Rules

  • Issues: task tracker. Assign, label (good first issue), link PRs with “Closes #n”.
  • Projects (kanban): Todo → In Progress → Done.
  • Actions (CI): auto-test every PR. Red ✗ = fix before merge.
  • Branch protection: Settings → require PR + 1 approval before merging to main.
  • CODEOWNERS / templates: auto-request reviewers, PR & issue templates (see .github/ in a real project).
Mission: On GitHub, open an Issue “Add my name to roster”, assign yourself, then open a PR that says “Closes #1”. Watch it auto-close on merge.

Graduation checklist

Progress saves in your browser. Do these for real in studying_github_collab.

    Cheat sheet

    git clone <url>
git checkout -b name/task
git add . 
git commit -m "Verb + what"
git push -u origin name/task
# open PR on GitHub → review → merge
git checkout main && git pull
git branch -d name/task

    Glossary

    main: protected default branch. PR: merge proposal. Fork: personal copy. Review: approve/comment. CI: auto tests. LGTM: “looks good to me”.

    FAQ

    Should I commit to main?

    No. Always branch. Protect main in Settings → Branches → Require a pull request.

    Fork or branch?

    Same repo + same team → branch. Outside contributor / classroom with no write access → fork, then PR from fork.

    I messed up — help?

    git status first. Wrong commit message: git commit --amend. Undo unstaged: git restore file. Unstage: git restore --staged file. Ask before reset --hard.

    HTTPS or SSH?

    HTTPS + personal access token is easiest to start. SSH is best long-term (no passwords).
